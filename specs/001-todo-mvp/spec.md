# Feature Specification: Todoアプリ コア機能（MVP＋段階拡張）

**Feature Branch**: `001-todo-mvp`

**Created**: 2026-07-16

**Status**: Draft

**Input**: User description: "対話で確定したスコープ — 基本操作（追加・完了チェック・削除）をMVPとし、完了/未完了フィルタ、タスク名の編集、期限（日付）を優先度順に含める。データはブラウザに保持。自分専用の個人用ツール。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 基本のタスク管理（追加・完了・削除） (Priority: P1)

利用者は、やることを思いついたらタスクとして書き留め、済んだら完了のチェックを付け、
不要になったら削除する。一覧を見れば「いま何が残っているか」が一目で分かる。
ブラウザを閉じて後日開き直しても、タスクは残っている。

**Why this priority**: これ単体でTodoアプリとして成立する最小の価値。他のすべてのストーリーの前提。

**Independent Test**: タスクを数件追加し、一部を完了にし、一部を削除し、リロード後も状態が
残っていることを確認すれば、このストーリーだけで完結して検証できる。

**Acceptance Scenarios**:

1. **Given** タスクが1件もない状態, **When** タスク名「牛乳を買う」を入力して追加する, **Then** 一覧に「牛乳を買う」が未完了として表示される
2. **Given** 未完了タスク「牛乳を買う」がある, **When** そのタスクの完了チェックを付ける, **Then** タスクは完了状態として見た目で区別できる（例: 打ち消し表示）
3. **Given** 完了状態のタスクがある, **When** 完了チェックを外す, **Then** タスクは未完了状態に戻る
4. **Given** タスクが3件ある, **When** そのうち1件を削除する, **Then** 一覧は残り2件になり、削除したタスクは表示されない
5. **Given** タスクを追加・完了・削除した状態, **When** ブラウザをリロードする, **Then** 直前と同じ一覧（件数・完了状態）が表示される
6. **Given** 入力欄が空または空白のみ, **When** 追加を実行する, **Then** タスクは追加されず、一覧は変化しない

---

### User Story 2 - 完了/未完了フィルタ (Priority: P2)

利用者は、タスクが溜まってきたときに「すべて / 未完了 / 完了済み」の表示を切り替えて、
残作業だけに集中したり、片付けた分を振り返ったりできる。

**Why this priority**: タスクが増えると未完了だけを見たくなるのは確実な需要。基本操作の次に
価値が高く、既存データに対する表示の切り替えだけで実現できる。

**Independent Test**: 完了・未完了が混在する一覧を用意し、各フィルタで表示される件数と内容が
正しいことを確認すれば単独で検証できる。

**Acceptance Scenarios**:

1. **Given** 完了2件・未完了3件のタスクがある, **When** 「未完了」フィルタを選ぶ, **Then** 未完了の3件のみが表示される
2. **Given** 同上, **When** 「完了済み」フィルタを選ぶ, **Then** 完了の2件のみが表示される
3. **Given** 「未完了」フィルタ表示中, **When** 表示中のタスクに完了チェックを付ける, **Then** そのタスクは未完了一覧から消える
4. **Given** フィルタ未操作の初期状態, **When** 一覧を表示する, **Then** 「すべて」が選択されており全タスクが表示される

---

### User Story 3 - タスク名の編集 (Priority: P3)

利用者は、登録済みタスクの書き間違いや状況の変化に合わせて、タスクを消して作り直すことなく
名前だけを直せる。

**Why this priority**: あると確実に便利だが、削除→再追加で代替できるため、フィルタより優先度は下がる。

**Independent Test**: 既存タスクの名前を変更し、変更が一覧とリロード後に反映されていることを
確認すれば単独で検証できる。

**Acceptance Scenarios**:

1. **Given** タスク「牛乳を買う」がある, **When** 名前を「牛乳と卵を買う」に編集して確定する, **Then** 一覧の表示が「牛乳と卵を買う」になり、完了状態は変化しない
2. **Given** タスク名を編集中, **When** 空または空白のみの名前で確定しようとする, **Then** 変更は保存されず、元の名前が維持される
3. **Given** タスク名を編集して確定した状態, **When** ブラウザをリロードする, **Then** 編集後の名前が表示される

---

### User Story 4 - 期限（日付）の設定 (Priority: P4)

利用者は、タスクに期限の日付を任意で設定でき、一覧上で各タスクの期限を確認できる。
期限を過ぎた未完了タスクは見た目で区別でき、後回しにしていることに気づける。

**Why this priority**: 個人用ツールとしての実用性を高めるが、タスク管理の本質（追加・完了・削除）
がなくても困らない付加情報のため最後。

**Independent Test**: 期限付き・期限なしのタスクを混在させ、期限の表示・変更・解除と期限切れの
区別表示を確認すれば単独で検証できる。

**Acceptance Scenarios**:

1. **Given** 期限のないタスクがある, **When** そのタスクに期限の日付を設定する, **Then** 一覧上でそのタスクに期限日が表示される
2. **Given** 期限付きタスクがある, **When** 期限を別の日付に変更する／期限を解除する, **Then** 一覧の表示が変更後の状態になる
3. **Given** 期限が昨日の未完了タスクと期限が明日の未完了タスクがある, **When** 一覧を表示する, **Then** 期限切れのタスクだけが見た目で区別できる
4. **Given** 期限が昨日の完了済みタスクがある, **When** 一覧を表示する, **Then** 期限切れの強調はされない（完了済みのため）

---

### Edge Cases

- 空文字・空白のみのタスク名で追加/編集した場合 → 受け付けず、一覧は変化しない（US1-6, US3-2）
- 同名のタスクを複数追加した場合 → 重複を許容し、それぞれ独立したタスクとして扱う
- 非常に長いタスク名（例: 200文字）→ 登録は許容し、一覧の表示が崩れない（折り返し等で全体レイアウトを保つ）
- タスクが0件のとき → 空であることが分かる表示を出す（何も出ないだけの画面にしない）
- フィルタ選択中に該当タスクが0件になったとき → 空表示とし、フィルタ選択状態は維持する
- 保存済みデータが読み込めない・壊れている場合 → アプリは起動し、空の一覧として開始する（クラッシュしない）
- 過去の日付を期限に設定した場合 → 設定自体は許容する（期限切れとして表示される）

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 利用者はタスク名を入力して新しいタスクを追加できなければならない（MUST）
- **FR-002**: システムは空または空白のみのタスク名の追加・編集を受け付けてはならない（MUST NOT）
- **FR-003**: 利用者は各タスクの完了/未完了を切り替えられなければならない（MUST）。完了タスクは一覧上で見た目で区別できること
- **FR-004**: 利用者はタスクを削除できなければならない（MUST）。削除は即時に一覧へ反映される
- **FR-005**: タスクの状態（名前・完了状態・期限）はブラウザのリロードおよび再訪問後も保持されなければならない（MUST）
- **FR-006**: 利用者は一覧の表示を「すべて / 未完了 / 完了済み」で切り替えられなければならない（MUST）。初期表示は「すべて」
- **FR-007**: 利用者は既存タスクの名前を編集できなければならない（MUST）。編集はタスクの完了状態・期限に影響しない
- **FR-008**: 利用者はタスクに期限（日付）を任意で設定・変更・解除できなければならない（MUST）。期限は必須ではない
- **FR-009**: 期限を過ぎた未完了タスクは一覧上で見た目で区別できなければならない（MUST）。完了済みタスクは期限切れ強調の対象外
- **FR-010**: タスクは追加された順に一覧表示される（MUST）。並び替え機能はこの機能の範囲外
- **FR-011**: 保存済みデータが読み込めない場合でも、システムは空の一覧として起動しなければならない（MUST）

### Key Entities

- **タスク（Task）**: 利用者のやること1件を表す。属性: タスク名（必須・空不可）、完了状態（未完了/完了）、期限（任意・日付のみ、時刻なし）、表示順を決める追加順。タスク同士に親子や依存関係はない

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 利用者は思いついたタスクを、画面を開いた状態から5秒以内・一連の操作（入力→確定）だけで追加できる
- **SC-002**: 追加・完了・削除・編集・期限設定のすべての変更が、リロード後に100%再現される（データ消失ゼロ）
- **SC-003**: フィルタの切り替え結果は体感で即時（1秒以内）に表示される
- **SC-004**: タスク100件を登録した状態でも、一覧表示と各操作が支障なく行える
- **SC-005**: 受け入れシナリオ（全ストーリー）の100%が自動テストで検証され、合格している

## Assumptions

- 利用者は本人1名のみ。ログイン・アカウント・複数端末間の同期は範囲外
- 利用環境はPCのブラウザ（Chrome）。モバイル対応・オフライン対応の最適化は範囲外
- データは利用者のブラウザ内にのみ保持される。サーバーや外部サービスへの保存は行わない（憲法「技術スタック制約」に整合）
- 削除は確認ダイアログなしの即時実行とする（個人用の小規模ツールのため）。取り消し（Undo）は範囲外
- 同名タスクの重複は許容する
- 期限は日付のみ（時刻なし）。通知・リマインダー機能は範囲外
- タスクの並び替え・検索・タグ・優先度は範囲外（必要になれば別featureとして起票する）
- UIの表示言語は日本語
- 想定タスク件数は最大でも数百件程度
